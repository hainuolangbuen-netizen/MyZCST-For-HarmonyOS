## 1. 深色模式文字对比度

### 现象

「首页」深色模式下「我的卡片」标题是深藏青（`#011F5B`）压在深灰卡片上，几乎看不清；
`WebViewPage` / `LoginPage` 的「‹ 返回」也使用同一个颜色，在深色标题栏上同样难以辨认。

### 根因

- `base/element/color.json` 的 `brand_navy` 只定义了浅色值 `#011F5B`；
- `dark/element/color.json` **没有覆盖 `brand_navy`**，深色下仍然取 `#011F5B`；
- 部分弱化文字用 `text_secondary`，深色下 `#8A8F99` 对 `#2C2C2E` 的对比度偏低。

### 改动

- `entry/src/main/resources/base/element/color.json`：新增 `brand_navy_text`（`#011F5B`）。
- `entry/src/main/resources/dark/element/color.json`：
  - 新增 `brand_navy_text`（`#A9C2EE`，深色下的可读蓝）；
  - `text_secondary` 由 `#8A8F99` 提升到 `#A6ADB8`。
- 仅把**用作文字**的 `brand_navy` 换成 `brand_navy_text`，保留 `brand_navy` 作为
  选中分类的背景色（白字在深蓝底上仍然清晰）：
  - `pages/LoginPage.ets`：返回文字；
  - `pages/WebViewPage.ets`：返回文字；
  - `view/HomePage.ets`：「我的卡片」标题。

## 2. 微信水电缴费白屏 / 卡死

### 现象

进入「智能水电 / 水费查询」→ 点微信支付后，WebView 页面大面积变白，无法返回或继续操作。

### 根因

`WebViewPage` / `WebTab` 对 `window.open` 的处理是：

```ts
.onWindowNew((event) => {
  if (event.targetUrl.length > 0) {
    event.handler.setWebController(this.controller); // 把新窗口塞回当前页
  }
})
```

缴费页点击支付时通常有两种行为：

1. `window.open()` 打开支付收银台/空白窗，再把内容写进去；
2. 直接跳到 `weixin://...` / `alipays://...` / `intent://...`。

第 1 种会把当前页 controller 交给新窗口，原缴费页被替换成空白页；第 2 种会让
Web 组件尝试渲染它不认识的 Scheme，同样得到白屏。原代码也没有 `onLoadIntercept`，
所以没有任何兜底。

### 改动

- 新增 `common/WebLink.ets`：
  - `isWebUrl()` / `isExternalScheme()` / `isPaymentUrl()` 分类；
  - **自定义 Scheme 直接 `startAbility`**：`weixin://`、`alipays://`、`unionpay://` 不再先走 `openLink`。
    这一步是「商家格式有误」的关键：部分系统会把 `weixin://` 当普通链接交给浏览器，
    微信侧解析不到支付参数就会报商家格式错误；直接交给微信 App 才是正确路径；
  - H5 收银台（`https://wx.tenpay.com/...`、`openapi.alipay.com/...`）才走
    `openLink` / `startAbility + entity.system.browsable` 打开浏览器；
  - `openExternal()` 失败时尝试从 Scheme 的 `url=` 参数取出 H5 收银台，最后才复制链接提示；
  - 识别常见收银台域名（`wx.tenpay.com`、`tenpay.com`、`mclient.alipay.com` 等）。
- `pages/WebViewPage.ets`、`view/WebTab.ets`：
  - 新增 `onLoadIntercept`：只放行 http(s)/file/about/data/blob 且非收银台的主框架导航；
    支付 Scheme / 收银台 URL / `intent://` 交给 `WebLink.openExternal()`，不再导航当前页；
  - 重写 `onWindowNew`：
    - 用 `setWebController(null)` 明确拒绝新窗口，避免当前页被接管；
    - 空白窗口 → Toast 提示；
    - 支付 Scheme / 收银台 → 交给系统 App；
    - 普通 http(s) → 用新的 `WebViewPage` 打开（当前页保留，可返回）。
- 顺带修复了该页面深色标题栏「‹ 返回」不可见的问题（见第 1 节）。

> 说明：支付最终能否拉起微信/支付宝取决于设备是否安装对应 HarmonyOS 版 App 且
> 系统支持该 Scheme；即使拉不起来，也不会再出现白屏卡死，页面保持可用并给出复制链接兜底。

**改动**

  - 失败时只记日志、不覆盖旧数据；同一份数据 30 分钟内不重复请求，失败后 1 分钟内不重试。

## 3.4 直接导入鸿蒙原生课程表 / 日历的可行性

先给结论：**做“一键导出到系统日历”可行，做“双向同步的原生课程表”成本高**。
建议保留现在的小组件作为“今天上什么课”的入口，系统日历导出作为可选的第二入口，
不把课表完全搬进系统日历。

### 可用能力（本机 SDK 26 实测声明）

- `@kit.CalendarKit` → `@ohos.calendarManager`（API 10+）：
  - `calendarManager.getCalendarManager(context)`；
  - `getCalendar()` 取默认日历（需 `READ_CALENDAR`）；
  - `addEvent(event)` / `addEvents(events[])` 写事件（需 `WRITE_CALENDAR`）；
  - `updateEvent` / `deleteEvent` 可做增量同步；
  - `Event` 支持 `title`、`location`、`startTime`、`endTime`、`isAllDay`、
    `reminderTime`、`recurrenceRule`、`description`、`identifier`。
- 权限：`ohos.permission.READ_CALENDAR`、`ohos.permission.WRITE_CALENDAR`，
  `grantMode: user_grant`，必须在运行时向用户申请，不能静默写入。

### 两种方案

| 方案 | 工作量 | 优点 | 风险 |
| --- | --- | --- | --- |
| A. 一次性导出本周/今天课程 | 低（1 个页面 + 事件映射 + 权限申请） | 用户可在系统日历看到课程和提醒 | 课程调整后不会自动更新；重复导出需用 `identifier` 去重 |
| B. 整学期周课表 + 双向/增量同步 | 中高 | 真正的系统级课程表体验 | 需要处理调休、停课、换周、教室变更；要维护事件 ID 映射；权限被拒/撤销；多设备重复 |

### 建议实现顺序（若要做 B）

1. `CalendarExport` 模块：用 `CourseSync` 已解析的 `day/start/span/name/room` 计算
   具体日期与起止时间（需要补一份节次时间表，例如 1-2 节 08:10–09:50）；
2. 用 `identifier = course_<term>_<week>_<day>_<start>_<name>` 做幂等键；
   导出前 `getEvents` 按 `identifier` 查重，或本地保存 eventId 做 update/delete；
3. 写入 `recurrenceRule`（每周）或按周批量写入；调休/停课在同步时删除对应事件；
4. `module.json5` 声明 READ/WRITE_CALENDAR，设置页加「导出到系统日历」并处理拒绝授权；
5. 失败/撤销时回退到卡片，不影响主流程。

### 结论

- **短期**：先把卡片做成“今日课程列表”（本次已做），成本最低、打开即见；
- **中期**：加一个可选的「导出本周课表到系统日历」，用 `identifier` 去重，收益/成本比最高；
- **不建议**把系统日历当唯一数据源：学校课表有周次、调休、临时调课，系统日历无法反向驱动，
  最终仍要依赖 `CourseSync` 的接口数据。

## 4. 测试方法（真机）

### 4.1 深色模式

1. 「我的」→「设置」→ 深色模式选「深色」；
2. 回到首页，检查「我的卡片」「管理」文字能清晰辨认（原问题区域）；
3. 打开任意网页（应用页 → 学校官网）和登录页，检查左上「‹ 返回」可见；
4. 切换回「浅色」确认样式未回归。

### 4.2 水电缴费

1. 登录后进入「应用」→「智能水电 / 水费查询」（需要账号）；
2. 进入充值页，点「微信支付」；
3. 预期：不再出现整页白屏/卡死；`weixin://` 会尝试直接拉起微信（不再把 Scheme 丢给浏览器，
   避免「商家格式有误」），H5 收银台 URL 才交给系统浏览器；
4. 如果拉不起微信，页面会提示，可在系统浏览器完成支付后返回；
5. 返回键、刷新按钮仍可用；重复点支付不会把页面替换成空白。

### 4.3 课表卡片

1. 首页点「我的卡片 / 管理」→ 系统卡片管理页出现「今日课程」→ 选择尺寸添加到桌面；
   也可以从「我的 → 设置 → 卡片与同步 → 添加今日课程卡片」进入同一个入口；
2. 登录统一身份认证；登录返回后等待 2~5 秒，桌面「今日课程」应显示
   标题、`第X周 · 日期` 和当天课程列表（节次/课程/教室），内容从卡片顶部开始排列；
   没有课则显示「今天没有课程」；
3. 杀掉 App 再打开，卡片数据仍保留（来自 preferences）；
4. 换一天/换一周后再次打开 App，应按 30 分钟 TTL 重新同步；
5. 如果学校接口异常，卡片保留上次数据，不会清空；日志过滤 `myzcst-course` 可看到失败原因。

## 5. 潜在风险：学校接口改动会导致同步失效

`CourseSync` 用的是官方安卓版 RN 课表模块的**旧 iPortal 移动接口**（`mapp.zcst.edu.cn`
下的 `/_web/_lightapp/schedule/...`），这些接口：

- 没有公开文档，字段（`currentWeek` / `zj` / `jc` / `jccd` / `kcmc` / `jsdd`）是运行时探测的；
- 学校升级轻应用、改字段名、改路径或加验证时，同步会失败（`looksJson` 判定失败，
  或解析不到课程）；此时卡片保留旧数据，不会崩溃；
- 登录态依赖 WebView 的 mapp 域 Cookie，如果学校调整 CAS/Cookie 策略，也会导致同步失败；
- 修复位置集中在 `common/CourseSync.ets` 的 URL 常量与 `collect()` 字段列表，
  接口变更时只需改这一处并抓一次真实响应核对。

建议后续用测试账号抓一次真实 JSON 固化为单测样本，减少对线上接口的依赖。
